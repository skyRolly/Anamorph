## N2-01 — gated A(dry) re-entry

**Source / contract.** `AnamorphEngine::process`, `src/dsp/AnamorphEngine.cpp:1900-1960` and `:2015-2113`; `MultibandWidth::processBlock`, `src/dsp/MultibandWidth.cpp:118-210` and `:244-369`. ADR-0005 requires the dry contribution at partial Mix to follow the wet crossover phase; DSP_POLICY and SIGNAL_FLOW repeat the phase-matched reconstruction. The H4 gate and its performance tradeoff are recorded in `docs/architecture/PERFORMANCE_BUDGET.md:55`; its claim is that re-entry is comb-free. The dry *delay rings* stay populated, but their warmth is not the state of the dry crossover filters.

**Mechanism and reachability.** With Multiband enabled, Mix exactly 1, Match off and no Bypass/enable transition, `fullWetIdle` skips the dry filter bank while the wet bank keeps processing. A Mix dip makes `fullWetIdle` false and runs the dry bank with its old/cold IIR state. Copying current coefficients and maintaining delay-ring samples cannot reconstruct the omitted filter history. Its output is mixed against the warm wet bank as the Mix smoother moves. This is normal finite input, without a guard or self-heal. The supported parameter range includes the 20 Hz crossover used here.

**Reproduction.** `gate-probe.cpp`, `build-gate-probe.sh`, `gate-twin-baseline.csv`, `gate-twin-warm.csv`, `compare-gate-twins.py` and `.log`. Two unmodified engines, 48 kHz / 128 samples, Haas Amount 0, Multiband on, 2 bands, widths 1, crossover 20 Hz, Mix 1 and a 0.5-amplitude mono 20 Hz sine for 3 s. At block 1125 one engine targets Mix 0.5; the other stays Mix 1. With unit widths, both wet and phase-matched dry represent the same allpass output, so the continuously full-wet engine is an independent production oracle; Mono Maker, Level Match, Bypass and output trim are off. On the first 960 samples, actual minus full-wet has peak **0.1361084**, RMS **0.1014817**, and actual RMS is **2.5659 dB lower** than reference. At crossover/tone 50 Hz it is **0.4704 dB** lower and peak difference **0.0545571** in that window. At 20 Hz the error declines rather than latching: in samples 2880–4479 RMS error is **0.0008256**. The same scenario through `AnamorphAudioProcessor::processBlock` gives the same 0.1361084 peak, 0.1014817 RMS difference and −2.5659 dB (`processor-probe.cpp`, `processor-probe.log`). The comparison is a rendered transient, not a measured stationary comb response, listening result or DAW result.

**Control and causality.** A diagnostic variant changes only the H4 gate to keep the existing dry bank running (`always_dry.patch`); its 20 Hz dipped-Mix output is within **2.98e-8 peak** of the unmodified continuously full-wet twin in that first window. It is a counterfactual, not a proposed production patch or proof of an acceptable CPU cost. The existing Test 25 passes in the fresh suite but uses default crossover frequencies, broadband noise, an aggregate ten-block RMS threshold and no always-warm sample oracle; it does not rule out this low-frequency transient (V2-01).

**Disposition.** Preserve the accepted phase-matched topology. Determine how to maintain or restore sufficient dry-filter history without losing valid data, and assess the documented H4 CPU tradeoff before choosing a correction. A graph, signal-order, latency or threading change triggers the Architecture Review Gate; turning off an existing compute gate in place still changes CPU and numerical behavior and needs explicit owner review against H4's accepted optimization. Add the low-frequency continuously active twin and later recovery as regression evidence.

## N2-02 — crossfaded controls lost during an ordinary duck

**Source / contract.** `AnamorphEngine::copyContinuous` at `src/dsp/AnamorphEngine.cpp:831-851`; `adoptSnapshot` at `:871-1058`; switch bottom and fade-in completion at `:1431-1580`. ADR-0004 assigns Bypass and Multiband Enable to their own running crossfades, excludes them from `discreteDiffers`, and distinguishes an ordinary duck's immediately live controls from a forced swap's deliberate whole-destination deferral. They are host-facing parameters (`PluginParameters.cpp:281,324,419,434`; Multiband requires Advanced mode).

**Mechanism.** During an ordinary duck, `copyContinuous` saves and restores both `p.bypass` and `p.mbEnable` as if discrete. During fade-in `pendingP` is refreshed, but the bottom has already passed: no further bottom adopts it. If a toggle returns before the duck retires, every block's snapshot is valid yet neither control's smoother sees the pulse. If it stays on, it waits until the state machine returns to Normal; this report's measured witness is the completely missed return leg. The explicit forced-bulk freeze/adoption contract is a different path and is not challenged.

**Reproduction and controls.** `probe.cpp`, `baseline-expanded.log`, `live_toggle.log`, `live_toggle.patch`. Four identically prewarmed production engines, 48 kHz / 64 samples, non-neutral stereo and Width 1.8; two request an ordinary Haas-to-Velvet algorithm change, two do not. For blocks 8–15 after the change (512–1023 samples; entirely after the ~6 ms duck bottom and inside fade-in), pulse Bypass on/off on one ducked and one unducked engine. Repeat separately for Multiband Enable with non-neutral band widths. The ducked pulse/no-pulse pair has **0 differing samples** over 36 blocks for each control; the unducked pulse/no-pulse controls differ in **1,982** and **2,174** channel-samples, peak **0.4605** and **0.9024**, respectively. The duck/no-duck comparison peaks at **0.8616**, confirming the ordinary transition had an observable effect. Thus this is not a transparent-chain oracle. A temporary variant that lets just these values pass through `copyContinuous` produces 1,982 / 2,174 differing samples in the ducked comparisons, peaks **0.2330 / 0.6853**. That isolates the preserved-value mechanism; it is not a reviewed general fix. A second matrix (`overlap-matrix.cpp`, `overlap-matrix.log`, `overlap-live-matrix.log`) covers 44.1 and 48 kHz, both initial control states, and short return pulses wholly within fade-out or fade-in: all 16 baseline pulse/no-pulse comparisons have zero differences while all 16 no-duck controls differ; the targeted diagnostic makes all 16 ducked comparisons differ. The separate real-processor probe confirms raw parameter readback on/off = 1/0 for each pulse, 0 ducked-pair differences and 1,982 / 2,174 no-duck differences; its measured duck is nontrivial (`processor-probe.log`). Engine calls supply fresh snapshots every block, matching the processor's `setParametersFrom` path. No claim is made about a plugin wrapper or particular DAW.

**Disposition.** Let independently crossfaded controls respond under ordinary transitions while preserving the forced-bulk complete-snapshot rule and boundary/reset semantics. Cover both controls, fade-out and fade-in, held and returned toggles, interruption, re-entry and forced swaps with a non-neutral twin. This can be independent of N2-01/N2-03 and changes currently missed automation behavior by design.

## N2-03 — Multiband Enable endpoint bits

**Source / contract.** `AnamorphEngine.cpp:1912-1925,1963-2003`: ADR-0004 expressly requires bit-exact Multiband Enable endpoints. `blending` is chosen once per block, but the inner loop keeps calculating `pm + b*(wet-pm)` even after `b` reaches one; the settled next block skips it. The aligned-dry interpolation uses the same form. An endpoint selected only once per block cannot cover the remaining samples in the ramp's final block.

**Evidence.** `probe.cpp`, `trace-stderr.log`, `baseline.csv`, `endpoint.csv`, `compare.log`, `endpoint.patch`. 48 kHz / 127-sample blocks, 2/3/4 bands, unequal stereo, non-neutral band widths, Mix 1 and 0.4, both directions. The trace reports the terminal tick at offset **67** of the fifth transition block, `b=1`. In the 4-band left wet branch the independent destination is `0x1.ba8d6cp-5` (float bits `0x3d5d46b6`), whereas the actual blend is `0x1.ba8d6p-5` (`0x3d5d46b0`): **6 ULP**, or **2.23517418e-8**. The instrumented output CSV is equal to uninstrumented baseline. A diagnostic per-sample endpoint-selection variant differs at **151 channel-samples** across the tested rows, max **5.96046448e-8**, including terminal/post-terminal samples in the same block. Disabling (`b=0`) produced no differing finite output samples in this focused matrix. The aligned dry output also had terminal-bit differences in the trace. The current click/no-mute Test 23 has no exact endpoint oracle; this is not a claim of an audible defect.

**Disposition.** Preserve existing interior rounding and smoother ticks; explicitly cover the exact terminal sample and later samples in that block, in both wet and dry reference. A focused stage-local correction is suitable for 0.10.2; broader arithmetic changes would affect valid samples and require separate evidence.

## N2-04 — conditioned dry history after a wet self-heal

**Source / contract.** `AnamorphEngine.cpp:2015-2113` writes both conditioned dry rings, and `:2281-2327` clears them on any detected output non-finite. ADR-0009 requires recovery; D-02 separately preserves raw bypass data. Resetting invalid histories remains necessary, but a wet/output-gain failure does not establish that every sample of both conditioned dry histories is invalid.

**Reproduction.** `heal-probe.cpp`, `heal-baseline.log`, `heal-trace.log`, `heal-trace-stderr.log`, `heal-retain.log`, `retain_dry.patch`: 48 kHz / 64, Haas Amount 0, Drive 0, Mix 0, +24 dB output, selected 8x (latency **6**). This deliberately uses the **base-rate latency stand-in**, not the wrapped filters: `osActiveFor` is false, and no wrapped-path claim is made. After warmup a finite `1e38` spike occurs only on the left; the right is constant 0.25. A twin substitutes ordinary left input. The output-gain multiplication overflows on the left, and an output-identical trace reports **one HEAL**. In the following block the unaffected right channel has **six zeros instead of six 3.9622333 samples**, then matches the twin for the rest of the block and the following two blocks. The diagnostic variant retains the two dry rings while retaining all other reset logic; the right channel has **zero differing samples** after the event. This isolates the ring clearing but does not establish that retaining a poisoned ring is safe.

**Disposition.** Separate valid conditioned history from history that might contain invalid data before preserving it; examine both channels, latency compensation, subsequent parameter changes and state recovery. An unconditional removal of reset is unsafe and is not recommended from this experiment. This is extreme-input-only, independent of raw Bypass preservation; suitability is conditional on a bounded, real-time-safe design and an adversarial invalid-history test.

## N2-05 — Mix=0 loses a finite dry input

**Source / contract.** `MidSide.h:38-45` computes `(L+R)*0.5f` and `(L-R)*0.5f`; `AnamorphEngine.cpp:2042-2113` computes `dry + m*(wet-dry)` even for exact zero. ADR-0005/DSP_POLICY require the conditioned, latency-aligned Mix=0 null; the final graph can legitimately change this at later enabled stages, all disabled in this witness.

**Reproduction / controls.** `baseline-expanded.log`, `mix-zero.log`, `mix_zero.patch`, `trace-stderr.log`: 48 kHz / 64, OS off, Haas Amount 0, Width 1, Mix 0, unity later stages, equal finite L/R **2e38**. Width's finite `L+R` operands overflow before multiplication by 0.5; the wet result is non-finite. `0 * (wet-dry)` then yields NaN and the existing guard scrubs all **128/128** otherwise finite conditioned dry output samples to zero and resets state. Trace reports the guard; next valid 0.25 block returns 0.25. The production processor likewise outputs zero for the extreme first sample and 0.25 after recovery (`processor-probe.log`). The same test at 0.25 and 1e20 preserves **128/128** dry samples. A diagnostic exact-zero Mix selection returns **128/128** original extreme values, isolating the masking failure; it deliberately does not solve detection/reset of invalid wet state. No assertion is made that this diagnostic is a complete safe correction.

**Disposition.** Preserve the dry endpoint without hiding invalid wet state from the required recovery. Consider the separate avoidable M/S intermediate overflow as part of the mechanism, using exceptional-only arithmetic to avoid changes to established finite rounding. No limiter or signal-order change is proposed. This is P3 because the demonstrated trigger is near float limits.

## N2-06 — Mix=1 cancellation

**Source / contract.** `AnamorphEngine.cpp:2042-2113`. The documented H4 optimization accepts omitting an m=1 reblend in one settled-full-wet configuration and its measured LSB-level change; it does not establish bit-exact Mix=1 in all configurations. This witness instead shows a material failure of the intended finite wet signal.

**Reproduction / controls.** `probe.cpp`, `baseline-expanded.log`, `mix-one.log`, `mix_one.patch`: 48 kHz / 64, OS off, Multiband off, Drive 0, Haas Amount 0, Width 0, Mix 1, input `(100000000, -99999992)` on both channels. The global Width operation's finite mono result is mathematically and in float `(4,4)`. The subsequent `dry + 1*(wet-dry)` returns **(0,8)** due to cancellation. A diagnostic selection of the existing wet endpoints returns **(4,4)**. The full-wet H4 fast path does not apply when Multiband is off. Unlike N2-05, all operands and outputs here are finite; the non-finite guard cannot correct it.

**Disposition.** Assess a narrowly exceptional endpoint treatment and regression; a global Mix=1 bypass alters ordinary rounding in configurations where it currently executes and should not be assumed safe. P3, extreme inputs only.

## N2-07 — Drive saturation canceled by its own interpolation

**Source / contract.** `AnamorphEngine::processNonlinearRegion`, `src/dsp/AnamorphEngine.cpp:1266-1365`, uses saturated `s = driveTanh(g*x)*c` then `x += blend*(s-x)`. At Drive 6 dB the settled blend is one. The documented waveshaper should saturate to finite ±1 with finite makeup.

**Reproduction / controls.** `drive-probe.cpp`, `drive-isolated-baseline.log`, `drive-isolated-endpoint.log`, `drive_endpoint.patch`: 48 kHz / 64, OS off, Haas Amount 0, Drive 6, Mix 1, one-band Multiband enabled. This selects the documented settled-full-wet H4 path, so the separate Mix reblend in N2-06 is skipped. Equal-channel finite input **±1e8** produces **0** in the unmodified engine; a diagnostic settled-Drive endpoint selection yields **±0x1.09a52ep+0** (about ±1.0377), and the 0.25 ordinary control agrees between them. The guard sees only finite zeros. Separate `drive-endpoint.log` and `drive-mix.log` show why correcting Drive alone can still be hidden by the downstream Mix=1 cancellation when H4 is not active.

**Disposition.** Consider a narrow endpoint/exceptional cancellation correction, with ordinary float-bit preservation and both smoothed and settled paths examined; a global rewrite would change established numerical behavior. P3, extreme inputs only.

## V2-01 — H4 verification claim exceeds the test's evidence

`testDryAlignGateRecomb` (`tests/dsp_tests.cpp:1554`) tests broadband noise at the default splits, accumulating ten transition blocks and accepting an out/in RMS ratio above 0.90. That assertion is valid for its chosen aggregate; it is not an exact phase or worst-frequency oracle. The published statement in `PERFORMANCE_BUDGET.md:55` that H4 re-entry is comb-free cites this test. The current suite passes while N2-01's independently reproducible two-production-engine case yields a **2.5659 dB first-window loss** and **0.1361 peak sample difference**. For a sharper negative control, applying the same ten-times-256-sample aggregate RMS threshold to the 50 Hz crossover/50 Hz tone from the 128-sample-block probe gives 0.9813, passing >0.90 despite the measured 0.4704 dB first-20-ms loss and 0.0546 peak deviation. This is an evaluation of the same criterion on the focused probe, not a claim that the unchanged Test 25 ran with those settings (`test25-oracle.py` / `.log`). The tonal measurements show transient reconstruction and level error, not a measured stationary comb response. They demonstrate that this proxy cannot establish the broader phase-aligned re-entry claim, beyond merely a missing arbitrary test. Narrow the claim now or strengthen the evidence with low split frequencies, targeted signals, a continuously active twin and recovery. Coordinate the new failing assertion with N2-01's correction. No assertion should be weakened merely to make the suite pass.

## Rejected, existing and deferred hypotheses

- **Selected oversampling implies wrapped DSP:** rejected as a premise. N2-04 intentionally proves the opposite configuration (Haas, Drive zero: selected 8x latency stand-in). The OS endpoint experiment separately executes a wrapper during Drive-triggered crossfades. The corrected D-02 test's modulation-only wrapped-path premise is present in the fresh suite.
- **Every m=1 rounding difference is a bug:** rejected. H4's skip of the float reblend is explicitly documented as Class B. N2-06 is instead a `(4,4)` to `(0,8)` finite cancellation at extreme input, and N2-01 is new low-frequency re-entry evidence against the documented comb-free claim.
- **Non-finite output means permanently broken engine:** rejected for the specific N2-04/N2-05 stimuli. The unaffected channel recovers after the six lost history samples and normal input resumes in the next Mix=0 block. This does not establish general recovery from every state poison.
- **All dry histories should always survive self-heal:** rejected as an unsafe generalization. The diagnostic retention in N2-04 is causal evidence for a finite-input case; invalid input can legitimately contaminate a delay ring.
- **D-01, T-01, D-02, R-01:** already fixed; no regression of those exact mechanisms was established. N2-04 concerns conditioned dry delay read by Mix with Bypass off, a separate state owner and consumer.
- **H4 / Level-Match measurement offset, processor non-finite parameter policy and listener-lock residual:** existing accepted or tracked boundaries. N2-01 does not by itself authorize abandoning phase-matched reconstruction or changing Level Match semantics.
- **Further follow-up:** longer held requests, rapid enable reversals and retained-state tests; lower-frequency/rate/block variants; safe conditioned-state preservation after genuinely invalid history; and OS-crossfade endpoint/interior overflow with actual wrapped processing are concrete, bounded experiments. Unmeasured broad concurrency or DAW scenarios are deferred, not findings.

## Recommended work queue and PR boundaries

1. **N2-02**: isolated ordinary-duck crossfade adoption, with engine and processor pulse/hold/return controls and forced-bulk negative controls. No dependency on the numerical findings. Expected to change audible automation timing where the request is currently dropped.
2. **N2-01 + V2-01**: choose the dry-bank warm-state and CPU tradeoff, preserving the existing filter topology and phase contract; add the exact continuously active twin and low-frequency regression. The verification claim can be narrowed independently, while a new regression that expresses the correct behavior will fail until the production correction. A change adding/removing/reordering a node, changing latency or threading requires Architecture Review. The current H4 optimization and performance consequences require owner review even if an in-place gate change is not itself a graph change.
3. **N2-03**: a separate stage-local endpoint patch and bit oracle. Preserve valid interiors, both dry/wet stage boundaries, and return legs. Its measured normal-audio numerical changes are small but intentional.
4. **N2-04**: investigate a safe finite-history ownership/validation rule and an invalid-history negative control before a patch. This may share recovery tests with N2-05, but its root cause and PR need not be coupled to Mix endpoint arithmetic.
5. **N2-05, N2-06 and N2-07**: each has a separate arithmetic mechanism and should be evaluated separately, with exceptional-path corrections if chosen; test that ordinary finite results stay bit-identical and that invalid wet state still heals. N2-07 can be hidden by N2-06 in the full engine, so retain the H4-isolated Drive oracle. These are low-priority extreme cases and can be deferred to a later maintenance cycle if the safe correction changes normal arithmetic or substantially complicates recovery.
