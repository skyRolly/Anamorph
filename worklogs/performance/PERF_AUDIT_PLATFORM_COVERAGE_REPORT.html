4The two special focuses

Windows MSVC and /arch:AVX2

verified against live Microsoft documentation
  1. Not assumed equivalent — and it isn't. /arch:AVX2 enables AVX2+FMA+BMI (a Haswell-congruent floor); contraction is governed separately by /fp.
  2. The default changed in VS2022: /fp:precise no longer emits contractions; /fp:contract is the new opt-in. So on 14.3x+ toolsets the flag is expected scalar-bit-exact — contraction off by default, not by pin, a materially weaker guarantee than the GCC/Clang pair.
  3. The open question is the vectorizer (reduction reassociation) — exactly what only a twin dump can answer, which is option 5's stated ground.
  4. The instrument is feasible: dsp_dump.cpp is verified platform-neutral; a Windows job can build it twice and diff 32 hashes as a same-machine A/B.
  5. Windows-only caveat: the x64 UCRT dispatches transcendentals by CPU at runtime (FMA3), so Windows output is already machine-class-dependent today — before any flag.

R-1 executed · instrument live, first result below adoption still deferred

ARM64

already covered, by the architecture itself
  1. FMA contraction is live at AppleClang's default via base-ISA FMLA — the codegen ADR-0031 declined on x86-64 to stay Class A.
  2. Vectorization needs no flag: NEON (128-bit) is unconditional; there is no 256-bit NEON and no SVE on Apple consumer silicon, so AVX2's width win has no arm64 analogue — architectural, not a hole.
  3. The one equalizing action is forbidden: -ffp-contract=off on arm64 was option 4, rejected — Class-B on shipped numerics, closing only half the cross-slice difference (24/32 scenarios differ via libm regardless).

R-2 · no action

A7-9's mechanism differs here — the glide walks to an exact 0 instead of stalling — and the fixpoint gate parks correctly regardless. What is x86-specific is the comments' account, not the code (F-1).

5Findings the tree does not yet say

F-1

The A7-9 stall has three platform-dependent terminal states; the shipped comments describe only the x86 one (~FLT_MIN/k). FTZ-off stalls at a ~7e-43 subnormal; contracted+flush walks to an exact 0. The fix parks correctly in all four measured configurations — the comments are what is x86-specific.

F-2

Test 41's no-FTZ comment states a measured falsehood — the glide does not walk "to a true zero" without FTZ, and the exact-zero check would still fire pre-fix. Wrong in the conservative direction, but wrong.

F-3

Windows bit-identity is machine-class-dependent today via the UCRT's runtime FMA3 transcendental dispatch — before any flag change, and a nuance the compatibility documentation does not yet carry.

F-4

The gate/loop contraction-mismatch family has four members, and one is not silence-confined: Velvet's density gate guards the gather on engaged signal. Test 40 is the standing guard for exactly that divergence. Practice-impossible and guarded — different strengths, both present.

F-5

juceaide and the VST3 manifest helper compile outside AnamorphHardening — configure-time host tooling, never shipped.

F-6

GNU-driver clang targeting the MSVC ABI would take the GCC/Clang branch and receive -march=haswell against the MSVC ABI — latent, exercised by no toolchain.

F-7

Linux CI executes AVX2 binaries unprobed; a pre-Haswell self-hosted runner would SIGILL in every job that executes engine binaries. The one executed binary outside the hardening target (the bare-clang++ RTSan canary) would be unaffected.
