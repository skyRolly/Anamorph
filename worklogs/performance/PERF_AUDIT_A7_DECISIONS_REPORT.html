Anamorph A7 Decision Brief

A7-2B has landed: the history image is gone and the gather reads the ring in place, bit-identically, taking 37 % off the worst block. The AVX2 question turned out to be two questions, and two thirds of that win needs no bit to change. And the glide-stall item shrank by 89 % the moment A7-2B made the path it is stuck on cheap.

One figure in this brief is wrong: the A7-9 bound

4.476e-36 is not a stimulus-independent bound. It is the maximum the investigation's own harness observed. Driving ±0.7 noise — the amplitude the DSP suite uses — Test 41 measures 1.563e-35 (Chorus, 192 kHz), 8.043e-36 (Haas, 48 kHz) and 7.145e-36 (Velvet, 48 kHz) against the same pre-fix sources: 3.5× the figure quoted below. The residual is a_stall × (wet term), so what bounds it is FLT_MIN/k times the module's wet gain — derived per module inside the test rather than quoted.

The direction of the change is unaffected, and the decision does not move: the residual is what the fix removes, and after it the silence output is an exact zero, which is stronger than any bound. At the corrected worst case, 1.563e-35 is ≈ −696 dBFS — some 25 orders of magnitude below the smallest accepted Class-B precedent. It is corrected here because a number quoted in policy-adjacent documents should be the one that is true. Full account: worklogs/performance/PERF_AUDIT_A7-9_AVX2_IMPLEMENTATION.md §4c.

A7-2 — gather straight from the ring

The design holds. The test that guards it does not.

Variant B deletes the linear history image entirely and reads each tap directly out of the ring as one to three unit-stride runs. It was rebuilt this round as the plan describes — the previous prototype still carried the image — and re-verified.

The correctness argument is stronger than the measurement. Every ring read can be hoisted ahead of the per-sample loop because a read at sample i could only touch this block's own write if size ≤ k-1, and k is capped at decorrSamps-1, which is smaller than the ring. And bit-exactness follows from the split being along i, not along t: every accumulator still receives exactly one add per tap, in ascending tap order, from the same zero-filled +0.

The finding that changes the plan

Test 39's oracle cannot see the likeliest defect

Test 39 compares the build under test against itself at different block lengths. There is no reference implementation in it, so its comparison cannot see a defect that is a pure function of the sample stream — the same wrong answer at every block length. The likeliest A7-2B defect is exactly that shape: a uniform one-sample error in the tap delay.

Correction to an earlier version of this brief. It reported that seeding that error leaves Test 39 green. That was measured on a harness reproducing Test 39's comparison but not its schedule. Against the committed test the seed is caught — but through the schedule, not the oracle, and only where the run crosses from the gather to the per-sample loop.

The oracle needs no product change — and it is now in the tree

prepare() sizes accum from maxBlockSize, and the gather gate requires numSamples ≤ accum.size(). An instance prepared for a smaller block therefore runs the per-sample loop over the same audio, with an identical ring, tap set and coefficients — those depend only on sample rate and seed. Assert the two bit-identical. Verified clean over 44 cells on the shipped engine, and live against the seeded defect.

Landed as Test 40 (testVelvetGatherEqualsPerSampleLoop): 24 checks across 44.1/48/96/192 kHz × blocks 32/128/512/4096 plus a density-1.0 pass, taking the suite from 178 to 202. The 4096 case exceeds decorrSamps at 44.1 and 48 kHz, so every tap splits — a regime Test 39 cannot reach — and density 1.0 activates all 64 taps against the default 0.5's shallow 32.

A7-5 / W5-D — AVX2

A twenty-percent win that is not a compiler flag decision

There is no explicit SIMD anywhere in src/ and no architecture flag anywhere in the build — -march, -mavx, -mfma, -ffast-math, -ffp-contract, /arch: and /fp: appear in zero of CMakeLists.txt, the workflows and the scripts. The only mention is the record of their deliberate absence: “numerics-affecting flags are frozen” (CMakeLists.txt:82-84, citing ADR-0021).

Twin-dump comparison (32 scenarios)Scenarios differing
GCC 13 baseline vs Clang 18 baseline — frozen flags0 / 32
GCC baseline vs GCC -march=haswell32 / 32
Clang baseline vs Clang -march=haswell32 / 32
GCC haswell vs Clang haswell32 / 32

The mechanism is the decision. Both toolchains permit FP contraction by default, but the frozen x86-64 baseline has no FMA instruction to contract into — so the default is inert and the two compilers agree bit for bit. Enabling AVX2 activates it, and because GCC and Clang contract differently, it simultaneously breaks the agreement between the two toolchains the project builds with. The freeze is currently doing more than its own comment claims: it is what makes the GCC-LTO job and the Clang jobs mutually verifying.

What it buys

Run this before drafting the ADR

AArch64's base ISA includes FMLA unconditionally — there is no flag and no baseline without it. Under the same contraction defaults, the compiler may already be contracting on the arm64 slice of the shipped universal binary, which would mean the two slices are already not bit-identical to each other. Nothing in the repository has ever checked.

The check is one job step and needs no new tooling: on the existing macOS runner, build AnamorphDspDump once for arm64 and once for x86_64, run both (the x86_64 one under Rosetta, as the suites already are) and diff the 32 hashes. It is an A-vs-B comparison of two builds — the only question the harness is allowed to answer — so it needs no stored baseline. The answer changes what the ADR is deciding.

Runtime dispatch is not the escape. It removes the compatibility cliff but makes the numerics worse-defined: the same binary then produces different bits on different CPUs, and every property built on bit-identity — the twin-dump bump gate, the GCC/Clang cross-check, AnamorphDspDump's entire reason to exist — becomes conditional on the machine that ran it. A hand-written, explicitly FMA-free AVX2 kernel for the LR4 crossover is the only variant that could stay Class A, and it is strictly more work than the flag for a fraction of the gain.

A7-9 — the glide that never reaches zero

Not one module. Three.

The glide is a += k * (target - a). With a zero target that is a -= k*a, and under the audio thread's ScopedNoDenormals the decrement underflows before the state does: once k*a falls below FLT_MIN it flushes to exactly zero and a stops moving. The fixed point is absorbing — the next decrement is exactly 0.0, forever. It is not a magic constant but a closed form, ≈ FLT_MIN / k, approached from below.

The recurrence holds no sr, so the stall follows the sample rate exactly as far as k does — and that differs by module. Velvet and Haas glide at compile-time constants, so their stall really is rate-independent. Chorus is the exception: wSmooth = 1.0f / std::max(1.0, 0.01 * workingRate), so 1/480 holds only at 48 kHz and the stall scales linearly with the rate.

The same sentence, wrong in three places

All three parked fast paths justify themselves with the same claim — that the one-pole “flushes to true zero” under ScopedNoDenormals (VelvetNoise.cpp:233-235, HaasProcessor.cpp:51-53, ChorusEngine.cpp:73-74). It does not. So all three fast paths are unreachable after a user turns the control down; they are reached only from a fresh prepare() with the control at its zero default — the state each was measured in.

The one gate in the same file that survives is Velvet's density gate, and the difference is the whole lesson: it tests the fixpoint, so a stalled glide satisfies it. The three amount gates test the value, so a stalled glide defeats them.

The residual inherits the same rate behaviour, so the bound is not a single number: Velvet and Haas are flat, and Chorus overtakes Haas above 48 kHz. The bound over the supported range is set by Chorus at the highest rate, not by Haas at 48 kHz.

Two instances, identically built and identically driven; afterwards one has its glide forced to exact zero — precisely what a fix produces. On real signal the residual is exactly invisible: the stalled amount multiplies into a product that itself flushes to zero. Differences appear only on digital silence, where the dry term is +0 and cannot absorb them. Worst case across all three modules and all four rates as this harness measured it (see the correction at the top — driving ±0.7 noise it is 1.563e-35): 4.476e-36 — Chorus at 192 kHz, about −707 dBFS.

No Class-A fix exists, and that is not a failure of imagination — the residual is the thing that distinguishes the two states, so removing it is what “fix” means. The bound is roughly 26 orders of magnitude tighter than the tightest accepted Class-B precedent (H4, 2.4e-10) and 32 tighter than the loosest (H11, 8.2e-4).

A7-2T — the path-equivalence oracle Done

Landed as Test 40, before the gather rewrite rather than alongside it. No product change: the reference instance is under-prepared so the gather gate's own numSamples ≤ accum.size() clause routes it to the per-sample loop.

The ordering was the safety property. Landing B first would have left a window in which the change with the highest chance of a silent, uniform arithmetic error was in the tree and the only test competent to see one was not.

03

Approve the cross-slice experiment (A7-5E) Recommend yes

Diff the universal binary's arm64 and x86_64 slices with the harness that already exists. One job step. It asks whether a property the product assumes is actually true, and it should be answered before the AVX2 ADR is drafted rather than after.

04

Approve AVX2 in principle Recommend: not yetClass B

About 20 % engine-wide — more than every A7 item combined — but it changes 88.9 % of output samples, imposes an ISA compatibility floor with a SIGILL failure mode, and costs the GCC/Clang bit-agreement cross-check. It amends a frozen ADR-0021 property, which CLAUDE.md classes as a hard stop.

Blocked on decision 03 and on three sub-decisions: the acceptable error bound, the minimum supported x86-64 ISA written into COMPATIBILITY_POLICY, and what replaces the two-toolchain cross-check.

05

Approve A7-9 APPROVED & IMPLEMENTED 2026-08-22Class B — silence only

The largest single item on the roadmap, and it is not a new optimization: it restores three already-shipped optimizations to the state in which they were measured. Inaudible by construction — zero differing samples on real signal.

Preferred repair: change the three gates from a value test to a fixpoint test, mirroring the density gate three lines above Velvet's. Snapping the state is worse — it mutates DSP state rather than choosing a path.
