§6Decisions needed from the maintainer

D-1 — KI-027: move latency-notification delivery off the audio thread?

Defect (confirmed ×2): automation of Drive/Algorithm delivers the APVTS callback on the audio thread; on an oversampling engage/disengage crossing the JUCE chain takes locks, allocates and write()s inside processBlock; a concurrent GUI edit adds a priority-inversion window.

Candidate fix: in parameterChanged, when not on the message thread, set an atomic flag consumed by the editor's existing 24 Hz poll (plus a processor-side AsyncUpdater fallback for editor-closed sessions); message-thread calls keep the synchronous path. Latency VALUE and safe-point latch unchanged — only delivery timing moves, by at most one poll tick.

Why gated: threading-model + latency-delivery change — two hard-stop categories. Also reconciles the LATENCY_MODEL/THREAD_MODEL drift recorded in KI-027.

D-2 — RISK-007: guard off-main-thread state calls, or accept as documented?

Exposure: macOS AU autosave path only, in practice (VST3 forbids it; JUCE hosts lock around it). Options: (a) accept + keep documented (done in r1); (b) narrow mutex over the state-set members; (c) callAsync marshalling of the metadata tail. Recommendation: run R2-2 (TSan) first; decide on measurements.

D-3 — Level-5 audition for v0.9.6

RELEASE_POLICY precondition 7 is per-version. The 2026-08-15 audition covered v0.9.4; since then the x86-64 machine code changed everywhere (ADR-0031/0032) and 0.9.6 changed audible behaviour in the defective windows. A DAW session by a human is required; nothing in CI can stand in for it (TESTING_POLICY Level 5). Until then HANDOVER lists the tag as blocked by three human items (licence, checklist, audition).

D-4 — Version handling of this round

The round shipped as v0.9.6 (dated CHANGELOG section, renumbered first-tag references) per the repository's established pattern — every user-visible change set gets a version and no tag has ever been cut. Override if you want it folded differently; the 0.9.5 section's dated record was left untouched either way.
