## `AnamorphAudioProcessor` — `src/PluginProcessor.h`

The VST3/Standalone wrapper (`: juce::AudioProcessor, private APVTS::Listener`).

| Member | Signature | Responsibility |
|---|---|---|
| `prepareToPlay` | `void (double sampleRate, int samplesPerBlock)` | Prepares the engine through `engine.prepareFrom`: primes it from a fresh parameter read, prepares, then adopts a SECOND fresh read (never the prime's snapshot — ADR-0057, precondition 5); requests the latency report (synchronous on the message thread, one 20 Hz tick otherwise — D-1). |
| `processBlock` | `void (juce::AudioBuffer<float>&, juce::MidiBuffer&)` | Per-block: transport/seek detect → `engine.setParametersFrom`, which reads the parameter snapshot (`readEngineSnapshot` plus the momentary solo audition) BETWEEN its two acquire takes of the request word (ADR-0057) → `engine.process`. |
| `readEngineSnapshot` | `anamorph::EngineParameters () const` | The engine snapshot the processor reads: every automatable parameter's atomic (`seq_cst` loads, ADR-0057 precondition 2) and the Oversampling Setting. Any thread; lock-free. The processor hands it to the engine only as a reader (`setParametersFrom` / `prepareFrom`); tests hand it in at an interleaving they choose. |
| `isBusesLayoutSupported` | `bool (const BusesLayout&) const` | Accepts stereo→stereo, mono→stereo only. |
| `getStateInformation` / `setStateInformation` | `void (...)` | Full session save/recall (see `STATE_SERIALIZATION.md`). |
| `getBypassParameter` | `juce::AudioProcessorParameter* () const` | Returns the registered host bypass param. |
| `getAPVTS` / `getEngine` / `getPresets` / `getInternal` | accessors | Editor access to subsystems. |
| `undo` / `redo` / `canUndo` / `canRedo` / `pollUndoCoalesce` | Undo API | Custom per-A/B-slot undo (sound params only). An undo or redo is a bulk swap (ADR-0057): its duck request carries a sequence from a scoped `BulkApply`, whose completion is published after the entry's last parameter store. |
| `adoptPendingHostState` | `void ()` | Message thread only: adopts every restore an off-message-thread `setStateInformation` has handed over (D-2, ADR-0036). Called by the processor's timer, by `pollUndoCoalesce` and at every state-mutating entry point; a no-op when nothing is pending. It **drains to a fixed point** (§15): a restore arriving during an adoption is adopted in the same pass, so a caller that drains before it acts is acting on the state of every restore that has arrived. It is a drain, not a wait — it stops the moment the cell is empty and never blocks. |
| `applyAutoGain` | `void ()` | Locks measured Level-Match gain into Output Gain. Does nothing while the published gain is NaN (ADR-0007, note 2026-09-24). |
| `setSoloPreview` / `clearSoloPreview` | `void (int) / void ()` noexcept | Momentary solo audition (atomic, non-undoable). |
| `abSwitchTo` / `abCopyToOther` / `abActiveSlot` | A/B API | A/B compare living in the processor (survives editor close). A switch is a bulk swap (ADR-0057): `requestAbSwitch` carries its sequence, and its completion follows the destination's last parameter store, so the engine adopts the slot whole. A Copy writes no parameter and raises no request. |
| `abToggle` | `void ()` | The A/B toggle as its own operation (ADR-0036 §18). Drains any pending host restore, then derives the destination as the other slot of the **post-drain** active slot. The editor's toggle calls this; it used to compute `abSwitchTo (abActiveSlot() == 0 ? 1 : 0)` from a read taken before the drain, which a restore flipping the active slot turned into a no-op. `abSwitchTo (int)` stays the primitive for an explicit target, which is intent rather than a stale derivation. |

## `AnamorphEngine` — `src/dsp/AnamorphEngine.h`

Format-agnostic DSP orchestrator. Driven only by `EngineParameters`.

| Member | Signature | Responsibility |
|---|---|---|
| `prepare` | `void (double sampleRate, int maxBlockSize)` | Allocates all buffers/oversamplers; resets; **then snaps every smoothed value onto the current snapshot's targets** — the engine's own via `snapSmoothers()`, and each module's via its `snapToTargets()`, which the modules' own `prepare()` cannot do because it runs before the snapshot is pushed in (ER-DSP-09). A restored session therefore opens IN its sound instead of gliding into it. The Level-Match published result survives a re-prepare at the **same** sample rate whose snapshot (`primeParameters`) changes nothing the measurement reads, while that result is **current** — the measure has caught up with the last change to anything it reads, however it arrived (a live edit, a duck bottom, a forced swap), and `reset()` will not adopt such a change from an in-flight duck (ADR-0007, Amendment of 2026-09-25; Test 69, State test 133); an A/B slot's remembered value restored at a switch is current only if it was **measured** when the slot was left, at this rate, for the measurement inputs it is restored into (ADR-0007, Amendment of 2026-09-25, A/B provenance; Test 70, State test 134) — the analysis is re-armed, the result kept, and with Level Match on the applied Level-Match gain starts on that result (not at unity, so audio resumed below the silence→audio detector plays matched from its first block; Test 68, State test 132); any other re-prepare flushes it and the applied gain starts at unity (ADR-0007, Amendment of 2026-09-24, F13(2)). (Allocation happens here, never in `process`.) |
| `reset` | `void (ResetScope resetScope = ResetScope::everything)` | Lands an in-flight switch duck on its target FIRST — a forced swap (A/B, preset load, undo, redo) as its silent bottom would, smoothers snapped; an ordinary duck's live controls keep gliding. For Level Match it is not the bottom's exact twin: the reset re-arms the analysis whatever the swap, a pending A/B restore (or engine-API injection) is adopted on the next `process()` block, and the applied gain lands at the next silence→audio edge rather than through a Case-A landing — then clears every audio tail (module delay lines and filter banks, the oversamplers, the four delay rings, the Level-Match analysis), settles the Bypass / Multiband Enable / oversampling crossfades and re-latches the oversampling engagement. `everything` (called only from `prepare()`) also clears the whole Level-Match matcher and the meters — except that when `prepare()` keeps the Level-Match result (same rate, same measurement inputs, a current result) the matcher is re-armed instead. `audioTailsOnly` (the host reset, `AnamorphAudioProcessor::reset()`) keeps the published Level-Match gain and the meter latches, clears the live meter display, and re-seeds the Chorus / Dimension-D wet and depth. The node resets land the glides they snap (Haas delay, crossovers, band widths, Band Solo split); no other glide a live edit left in flight is snapped — the engine's smoothers, the Haas / Velvet amount, Velvet density and Mono Maker cutoff keep gliding — so a host reset equals a clean start (Level Match aside) only when none of those is moving. |
| `setParameters` | `void (const EngineParameters&) noexcept` | The engine API: adopts a snapshot; continuous live, discrete ducked. One acquire take of the request word; the snapshot is adopted only if no bulk swap was awaited before the take and the take found no new request, so the caller must have read it after the engine's previous call returned (ADR-0057, precondition 5). Sequence-0 requests behave exactly as before. |
| `setParametersFrom` | `template <typename ReadSnapshot> void (ReadSnapshot&& read) noexcept` | The processor's per-block entry (ADR-0057): takes the request word with ACQUIRE, calls `read` for the snapshot, takes the word again, and adopts the snapshot only when it is TRUSTED — no swap awaited after the first take, no new request in the second. Nothing is adopted while a bulk swap's completion is awaited; the swap starts, ducked, on the first trusted snapshot after its completion. `read` runs on the calling (audio) thread and must be real-time safe. |
| `primeParameters` / `primeParametersFrom` | `void (const EngineParameters&) noexcept` / `template <typename ReadSnapshot> void (ReadSnapshot&&) noexcept` | Adopt a snapshot wholesale before `prepare()` — no duck, no ramp (the activation route). Adopt only a trusted snapshot: while a bulk swap is being written the prime keeps the state it has, and the swap starts, ducked, at the first adoption that reads it complete — `prepareFrom`'s trailing one, or a block (ADR-0057). The first is the engine API (one take); the second reads between two takes. |
| `prepareFrom` | `template <typename ReadSnapshot> void (double sampleRate, int maxBlockSize, ReadSnapshot&& read)` | The processor's activation in its load-bearing order: `primeParametersFrom (read)`, `prepare`, then `setParametersFrom (read)` — a second fresh read, never the prime's snapshot (ADR-0057, precondition 5). |
| `setTransportPlaying` | `void (bool) noexcept` | Feeds transport edge (Velvet tail kill). |
| `process` | `void (juce::AudioBuffer<float>&) noexcept` | Runs the full serial chain in place. |
| `getLatencySamples` | `int () const noexcept` | Current PDC latency (integer). A function of `p.oversample` alone since ADR-0034 — not of whether the wrap is engaged. |
| `predictLatency` | `int (const EngineParameters&) const noexcept` | Latency for an arbitrary snapshot (message-thread safe). Reads `e.oversample` and nothing else, so it agrees with `getLatencySamples()` for any snapshot carrying the same factor. |
| `getScopeBuffer` / `getCorrelation` / `getLevels` / `getMatchGainDb` | accessors | GUI read access to analysis. |
| `requestAbSwitch` | `void (int fromSlot, int toSlot, int bulkSeq = 0) noexcept` | The A/B switch (message thread, lock-free; call before applying the destination slot's parameters; with a `bulkSeq` the switch is stashed until the swap's completion and its bookkeeping runs when the swap starts, against the unchanged source — ADR-0057): requests the masking duck and names the slot being left and the slot to restore. The engine records the slot being left — the published Level-Match value, whether it is **measured** (`LoudnessMatch::isResultMeasured`: the measure's confirmed answer, not merely current), the state and sample rate it was measured for (with the Velvet Density it played: a non-finite one is the one the Velvet held, ADR-0007, Note of 2026-09-26, the non-finite Velvet Density), and, when it is not measured, the measure's post-change evidence (`LoudnessMatch::Evidence`) — and at the duck's silent bottom restores the destination's record: at this rate, for the same measurement inputs (`measurementInputsDiffer`, each side with the Velvet Density it plays), a measured record as its value, measured, and one not measured as its post-change evidence's mean, measured, when that evidence is a measurement (share ≥ 0.5) — otherwise, and for any other rate or inputs, its value, not current (ADR-0007, A/B provenance, revision of 2026-09-26). The bottom also re-arms the analysis when the two slots differ in anything the measurement reads (ADR-0007, Amendment of 2026-09-24, F13(2)). A pending switch keeps its source; a second switch while a restore is armed records nothing (ADR-0007, Amendment of 2026-09-25, A/B provenance). |
| `forgetAbMatchMemory` | `void () noexcept` | A session restore replaced both slots: the next block resets every record to 0 dB, not measured, and drops a switch still pending (ER-STATE-20). It keeps a pending duck and a bulk swap's sequence and completion (ADR-0057). |
| `injectMatchGainDb` | `void (float) noexcept` | Engine API (atomic): restore a Level-Match value the CALLER asserts is a measurement of the state it is adopted with — consumed at the next forced bottom (with the same re-arm rule) or, with no duck, the next block, and adopted as measured. The processor's A/B switch does not use it (`requestAbSwitch`). |
| `requestDuck` | `void (int bulkSeq = 0) noexcept` | Force a masking duck around a bulk param swap (atomic, one read-modify-write; it never cancels a pending A/B switch). Sequence 0 (the engine API): the duck starts at the next block, as before. With a `bulkSeq` the engine adopts nothing until `completeBulkApply (bulkSeq)`, and the duck starts then (ADR-0057). |
| `completeBulkApply` / `kBulkSeqCount` | `void (int bulkSeq) noexcept` / `static constexpr int = 15` | A bulk swap's completion (message thread, lock-free): a RELEASE CAS, called after the swap's last parameter store; exactly one per request, on every exit path. Sequences run 1–15; an older sequence's completion is ignored (ADR-0057). |
| `getAdoptedParameters` / `isMatchResultMeasured` / `isBulkSwapPending` | read-only observers | For tests and diagnostics; they read audio-thread state, so call them on the audio thread or where the host contract keeps `process()` from running concurrently. |

## `ParamPointers` / layout — `src/PluginParameters.h`

| Member | Signature | Responsibility |
|---|---|---|
| `createAnamorphLayout` | `juce::AudioProcessorValueTreeState::ParameterLayout ()` (free fn) | Builds the entire APVTS parameter tree. |
| `normalisedAsRendered` | `float (const juce::RangedAudioParameter&, float)` / `float (const juce::AudioProcessorParameter&)` (free fns) | The normalised value mapped onto the grid the plug-in actually renders and stores: `convertTo0to1(convertFrom0to1(v))`. The DSP reads `getRawParameterValue()` (the denormalised, interval-snapped value) and both the preset and session formats store that same number, so this is what "the sound" means for every *has it changed?* comparison — the preset modified-marker and the undo / A-B coalescer both build their signature from it (ADR-0036 §17). It is also the ONLY equivalence any signature uses — two sounds are the same when their rendered values agree to five decimal places, with no tolerance layered on top (ADR-0036 §19). For an interval-snapped parameter that makes a sub-step move correctly not an edit; the four log-mapped frequency ranges have no interval, so for them every representable move reaches the signature. |

Round 10 briefly reconciled it against a live read-back within 1e-6; that window absorbed real automation writes into the baseline and is gone. Its stated FMA-contraction premise could not have applied in the build where the equality failed (ADR-0031 compiles it `-ffp-contract=off`, 0 FMA emitted); the equality is asserted because it *is* the product invariant, not because every toolchain has been measured. |
| `soundSignatureForSavedTree` | `static juce::String (const APVTS&, const juce::ValueTree& savedSound)` | The signature `soundSignatureFor` will return once `savedSound` has been loaded — i.e. the clean baseline of a preset whose file holds that tree (ADR-0036 §17). Derived from the tree alone, so a saved preset's baseline describes its own **bytes** rather than a second read of the live parameters. Resolves every parameter through the same helper `applySoundTree` uses, so the apply path and the baseline cannot disagree about what a file means. | `adoptPending` | `std::function<void()>` | Fired by `step()` before it reads the current row, so the processor adopts a pending host restore first and the prev/next step is relative to the **authoritative** selection (ADR-0036 §18). | `onAboutToSave` / `soundParamGeneration` | `std::function<void()>` / `std::function<juce::uint32()>` | The two hooks `saveUser` uses to keep the file and the clean baseline one coherent pair (ADR-0036 §16). `onAboutToSave` drains any pending host restore **before** the sound is captured, so the bytes are the session the plug-in is on. `soundParamGeneration` is no longer read by `saveUser` at all — §17 replaced its two reads and their retry with ONE capture, so there is nothing to re-check; it remains `isDirty()`'s memo generation. Both optional. |
| `onAboutToLoad` / `onSoundApplied` / `onLoaded` | `std::function<void()>` | The load bracket the processor installs. `onAboutToLoad` fires once a load has passed every refusal check and before its first parameter store (the processor flushes a settled edit and raises the forced duck with the swap's sequence); `onSoundApplied` (ADR-0057) fires right after the load's LAST parameter store, and the processor publishes the swap's completion there — exactly once for every `onAboutToLoad`, on every exit path an exception included (`SoundAppliedGuard`); `onLoaded` records the one undo step. ## DSP module public interfaces

See `DSP_ALGORITHMS.md` for per-module method signatures (prepare/reset/process/setters) and
the algorithm behind each. All modules follow the same contract: **allocation only in
`prepare()`; `process()`/`reset()` never allocate, lock, or do IO** (see
`REALTIME_SAFETY_AUDIT.md`).
