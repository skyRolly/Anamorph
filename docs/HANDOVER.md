# HANDOVER.md

Operational status snapshot for technical handover. Update on every release
(`docs/policies/DOCUMENTATION_LIFECYCLE_POLICY.md`). Facts are Verified from the repository;
fields with no repository evidence are marked `TODO` rather than invented (constraint C7).

Snapshot taken on `main` @ `2d0a906`, i.e. with the **v0.9.0 release-prep** change set (PR #87:
version bump → 0.9.0, CHANGELOG `[0.9.0]`, installers for all three OSes, user manual +
installation guide under `docs/user/`), the **v0.9.0 installer/packaging rework** (PR #89:
Windows component page + dual-path destination page, macOS `.pkg` component selection,
system-wide installs everywhere, flat ZIP-only release archives), the **release-hardening &
commercial-readiness audit** (PR #91: `NOTICE` + `THIRD_PARTY_LICENSES.md`, `SUPPORT.md`, issue
templates), and the **lean-package / flat-artifact / closed-source / internal-testing
documentation passes** (PR #92, PR #93, PR #94) merged — on top of the
v0.8.12 line plus all six post-v0.8.12 PRs (audit #81, state harness #82, JUCE 9 migration #83
(SHA-pinned, ADR-0022 — `Accepted` 2026-08-15), RH-PR-8 pipeline + artifact-integrity #84,
release rehearsal #85, product-readiness roadmap #86). The cycle formerly planned as "v0.8.13"
was written up as **v0.9.0**, in preparation for the **internal-testing phase** — see
`docs/COMMERCIAL_STATUS.md`.

**Superseded before tagging, four times:** v0.9.0 was never tagged. The vendor manufacturer-code
change (`Anmf` → `RTec`, **ADR-0023**, `Accepted` 2026-07-30) landed on top of it as v0.9.1;
**v0.9.2** (2026-08-07) landed on top of that; and **v0.9.3** (2026-08-11) now lands on top of
v0.9.2 with **six** GUI interaction fixes — the Multiband **add-split preview line** no longer
stalls while the pointer moves (the display's skip-identical-frame gate did not watch the preview
line's position); **the click that dismisses a pop-up now does nothing else** (JUCE re-delivers it,
so it could also close Settings, discard a half-typed preset name, toggle A/B or add a Multiband
split — one editor-level shield now takes that click for every pop-up type, with **KI-018** and
**KI-020** the recorded residuals); **an open menu no longer outlives the plug-in window** being hidden, closed or
sent to the background, where it used to be left floating always-on-top and could even pull a
background plug-in window back in front; two menu-rendering fixes (width measured from the item text,
which had clipped *Select All*; disabled items dimmed); and **Tooltips off now means off** (it
previously only lengthened the delay, which a visible tooltip bypassed). One **Changed** item is
user-visible layout: the Widen row's two drop-downs are now equal width with their join on the
column's centre line, and the Style/Focus caption follows its box. **Two installer changes ride
along, both outside `src/`:** the **Linux** installer now asks where to install and **defaults to
the user's own account** (`~/.vst3` + `~/.local/bin`, no root, no password; system-wide stays
available as choice 2 and `sudo ./install.sh` behaves as before), and the **macOS `.pkg`** is now
built with every component **non-relocatable and non-version-checked**, which is **INC-012** — a
re-install used to write over a copy the user had moved out of `/Applications` (or to the Trash)
and report success while the standard location stayed empty.
No `src/` change from either: no serialized state, parameter or DSP change, so 0.9.3 is state- and
sound-identical to 0.9.2. What 0.9.2 brought: the first `src/` change since 0.9.0 — the preset
drop-down no longer outlives the plug-in window (it was a free-standing menu holding a raw
LookAndFeel pointer and a raw `this`, which crashed on click after the editor was gone), factory
presets are identified by an immutable internal id instead of by name so a same-named user preset
is selectable in its own right, the Settings control `Window Size` is relabelled **UI Scale**, and
the installer component titles are title-cased. Saved-state schema, parameter surface and DSP are
untouched. **v0.9.4** (2026-08-21) now lands on top of v0.9.3 in
turn: two **Changed** entries — the **JUCE 9.0.0 → 9.0.1** dependency upgrade (ADR-0026), with no
`src/` change and no build-dependency change, and the **C++ standard 17 → 23** migration
(ADR-0027), whose only `src/` change is one added `#include`. No build dependency moved for either
and engine output is proven bit-identical across both axes — the two JUCE versions and C++17 vs
C++23 — so 0.9.4 is state- and sound-identical to 0.9.3 as well. One **editor-only** fix was added
to 0.9.4 on 2026-08-19: a control covered by an open drop-down no longer reports itself hovered
(`src/PluginEditor.cpp` `cursorIsOverOpenPopup()`), which touches no parameter, no serialized field
and no DSP, so that identity is unaffected. It ships under the **ADR-0025** rule-1 exception —
`docs/procedures/TESTING.md` §"Gaps in the automated coverage" carries the four disclosures, and
that entry now records a **measured** correction to the standing claim that the behavioural half of
editor interaction is out of reach: it was driven headlessly on Linux under `xvfb` for this fix.
Two adjacent defects were measured and filed rather than folded into that change — **KI-024** (the
Settings / About / Save-Preset overlays occlude the same way) and **KI-025** (the micro-animation
idle gate could seal on a still-lit control when the pointer left the editor inside one frame).
**Both were fixed on 2026-08-19** and removed from `KNOWN_ISSUES.md`: the overlay case by a general
per-widget occlusion test that derives what counts as an overlay rather than listing the three, and
the idle gate by giving its "nothing can move" condition the second half it lacked, with the ease
made to land on zero so the added condition cannot cost anything. Idle cost measured unchanged at
**0 passes/s** with the pointer outside, before and after. A third editor-only fix followed on
**2026-08-20**, and it is not another occlusion case: JUCE's tooltip tick mixes a CACHED answer to
"what is the pointer on?" with a LIVE reading of where the pointer is, and the tooltip's own
reposition rewrites that cache from the last event's position rather than the live one — so the box
lands where the pointer is and is labelled with where it was, until the next event. The cached
component is now checked against the live pointer before it is trusted. Two earlier attempts at this
defect were reverted first; both misdiagnoses are recorded in `DOCUMENTATION_COVERAGE.md` rather
than deleted.
**The release in preparation is therefore v0.9.7** and that is the first annotated tag
this project will cut (0.9.4 through 0.9.6 were, like their predecessors, written up and superseded
before a tag was cut — 0.9.5 by the A7 performance programme, 0.9.6 by the round-1
engineering-review fixes, 0.9.6 in turn by **ADR-0034**, the maintainer-instructed latency change of
2026-09-03). The rows below describe 0.9.7; the earlier detail is
retained as history. `docs/COMMERCIAL_STATUS.md` still
carries its 2026-07-26 review date — its content (product model, distribution model, open
owner/legal decisions) is unaffected by the version renumbering, and it is re-dated when its
substance next changes rather than on every version bump.
