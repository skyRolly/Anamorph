# UBSan instrumentation ignorelist -- TWO sub-checks, each in one third-party place.
#
# WHY IT EXISTS. The `sanitizers` job enables `implicit-conversion` on both the C
# and C++ flags. That flag instruments EVERY translation unit the build compiles,
# and this build compiles JUCE from source -- including the vendored third-party
# code inside it (HarfBuzz, FreeType glue, zlib, png, flac). Those libraries use
# narrowing assignment as ordinary idiom.
#
# WHAT MADE IT NECESSARY, rather than a precaution. The editor-lifetime test
# (`tests/state_tests.cpp`) constructs the real editor, whose constructor calls
# `refreshPresetDisplay()` -> `textWidth()` -> JUCE font shaping -> HarfBuzz. That
# reaches `hb-face.cc`:
#
#     face->num_glyphs = -1;      // num_glyphs is `unsigned int`
#
# HarfBuzz's documented "not computed yet" sentinel, deliberate and benign, and
# UBSan is correct that it narrows. It is not a defect and it is not this
# project's code, so failing the sanitizer job on it would train people to read a
# red `sanitizers` as noise -- which is the way a gate stops being read at all.
#
# THE SCOPE IS THE POINT, and it is as small as the mechanism allows:
#
#   * ONE SUB-CHECK PER SECTION. The `[implicit-conversion]` section header limits
#     the rule under it to that sanitizer. ASan, the rest of `undefined`, `vptr`,
#     `unsigned-shift-base`, `local-bounds` and `nullability` still instrument the
#     vendored tree in full, and `float-divide-by-zero` still instruments all of it
#     but the one file named in the second section below.
#   * ONE TREE. `juce-src` is where FetchContent puts the dependency
#     (`<build-dir>/_deps/juce-src`) and where `ANAMORPH_JUCE_PATH` points a local
#     checkout. No first-party path contains it, so no `src/` or `tests/` file can
#     be exempted by accident.
#
# `DEPENDENCY_POLICY`/`TESTING_POLICY` step 4 of the sanitizer procedure --
# "do not weaken the entire sanitizer suite merely because one third-party path is
# noisy" -- is what this file implements rather than the two alternatives that
# were available: dropping `implicit-conversion` from the flag set (weakens every
# TU, first-party included) or not constructing the editor under sanitizers
# (removes the coverage the test exists for).
#
# VERIFIED IN BOTH DIRECTIONS on the pinned clang-22, because an ignorelist that
# silenced everything would look identical to one that works: with a narrowing
# conversion seeded into BOTH a `juce-src` path and a first-party path, the
# vendored one goes quiet and the first-party one still fails the run.
[implicit-conversion]
src:*juce-src/*

# ============================================================================
# THE SECOND SECTION -- `float-divide-by-zero`, ONE FILE (round 30, 2026-09-16).
#
# `juce::Slider::Pimpl::mouseDrag` chooses between the absolute and velocity drag
# mappings with
#
#     isAbsoluteDragMode (e.mods) || (normRange.end - normRange.start) / sliderRegionSize < normRange.interval
#
# and `sliderRegionSize` is **0 for every rotary slider in every JUCE application**.
# The member is initialised to 1, but `Pimpl::resized` assigns it for the
# horizontal and vertical styles only -- and `juce::Slider`'s own constructor runs
# a layout while the style is still the default `LinearHorizontal` and the bounds
# are 0x0, which writes 0. The later `setSliderStyle (RotaryVerticalDrag)` re-runs
# the layout, takes neither branch, and leaves the 0 in place for the object's
# whole life. So the division is evaluated -- and it is evaluated exactly when the
# user holds the velocity-swap modifier (Ctrl/Cmd/Alt) and drags a knob, because
# that is the one case in which `isAbsoluteDragMode` does not short-circuit it.
#
# The result is IEEE +inf on every platform this ships to, `inf < interval` is
# false, and the velocity branch is taken -- which is what JUCE intends when the
# region is unknown, and what round 30's State test 106 measures end to end. There
# is no first-party expression to correct: the numerator, the denominator and the
# comparison are all JUCE's, and the only ways to change the denominator from here
# (laying the knob out at a chosen size while its style is still linear, or
# disabling the modifier swap) would either pick a region that flips the drag mode
# for coarse-interval controls or delete a JUCE behaviour nobody asked to lose.
#
# WHY IT SURFACED NOW rather than years ago: no test had ever dragged a knob with
# the velocity modifier held. State test 106 is the first, and it found this on its
# first sanitized run.
#
# THE SCOPE IS ONE FILE, not the tree: every other vendored source still has
# `float-divide-by-zero` instrumented, and `src/` and `tests/` cannot be reached by
# this pattern at all.
#
# IF YOU EDIT THIS FILE, ccache WILL NOT NOTICE (round 31). `-fsanitize-ignorelist=`
# changes what the compiler emits, but ccache 4.9.1 -- the runner image's version --
# has special handling only for the older `-fsanitize-blacklist=` spelling and hashes
# the new one as a plain argument string. Same path, edited content, cache HIT: the
# next build reuses objects compiled under the PREVIOUS list, and a section you just
# added does nothing. That is what happened to this section on its first push (CI run
# 35136379451 failed on the very check named below, hours after the same section was
# verified in both directions locally without ccache). `CCACHE_EXTRAFILES` in the
# sanitizers job now names this file, which is ccache's own mechanism for an input
# that affects the output without appearing in the preprocessed source -- and the
# same variable is what a local ccache build of the sanitized targets needs.
[float-divide-by-zero]
src:*juce_Slider.cpp
